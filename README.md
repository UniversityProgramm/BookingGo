# BookingGo

Сервис записи на визиты: Go API и адаптивный личный кабинет на React, TypeScript и Vite. Интерфейс на русском языке, с отдельными разделами клиента, сотрудника и администратора.

## Возможности

- Клиент: свои записи, фильтры по статусу, создание часового визита и подтверждение отмены будущей записи.
- Сотрудник: все записи, поиск, просмотр пользователей и завершение визита после его окончания.
- Администратор: все записи, поиск пользователей, создание клиента, изменение ФИО и телефона, подтверждение удаления пользователя.
- Для всех ролей: профиль, смена почты и пароля, TOTP, уведомления и предпочтения email/SMS.
- Загрузка, пустые результаты, ошибки с повторной попыткой, защита от повторной отправки форм и клавиатурная навигация.

Назначения ролей через интерфейс нет: существующий API его не предоставляет. Регистрация и создание пользователя администратором создают клиента. Сотрудники и администраторы должны уже существовать в вашей БД.

Свободное время проверяет сервер при отправке формы. При конфликте введённые данные сохраняются. Даты отображаются в часовом поясе браузера с явной подписью, запросы содержат RFC 3339. Дополнительных ограничений рабочих часов нет.

## Запуск через Docker Compose

Нужны Docker Desktop с запущенным движком и Docker Compose v2.

1. Скопируйте `.env.docker.example` в `.env.docker`.
2. Укажите в `DB_URL` пароль PostgreSQL из вашей конфигурации Compose и заполните `JWT_SECRET` случайным значением. Не коммитьте `.env` и `.env.docker`.
3. Подключите существующую БД BookingGo или восстановите её схему и данные в PostgreSQL. Проект использует уже подготовленные таблицы `users`, `bookings`, `notifications`, `outbox_events`; автоматическое создание схемы и новые миграции в эту задачу не входят.
4. Выполните:

```sh
docker compose up --build -d
docker compose ps
```

- Приложение: <http://localhost:3000>.
- Go API: <http://localhost:8080/api>.
- Swagger: <http://localhost:8080/swagger/index.html>.

Nginx раздаёт SPA и проксирует `/api/` в Go-сервис. Вложенные адреса, например `/client/bookings` и `/security`, можно открывать напрямую. PostgreSQL, Redis и NATS запускаются тем же Compose. Данные PostgreSQL и Redis сохраняются в томах.

```sh
docker compose down
```

Эта команда останавливает сервисы и сохраняет тома. Не используйте `down -v`, если хотите сохранить данные.

## Локальная разработка

Нужны Go 1.26+ и Node.js 22.16+ (либо поддерживаемая более новая LTS-версия). База PostgreSQL должна содержать существующую схему проекта.

```sh
# Инфраструктура
docker compose up -d db redis nats

# В корне: скопируйте .env.example в .env,
# заполните DB_URL и JWT_SECRET
go run ./cmd/server
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173>. Vite проксирует `/api` на `http://127.0.0.1:8080`; настройка находится в `frontend/vite.config.ts`. При изменении порта API обновите адрес прокси.

## Проверки

```sh
# Из корня
go test ./...

# Из frontend/
npm run typecheck
npm test
npm run build
```

Тесты фронтенда проверяют HTTP-клиент, обработку `401` и `403`, очистку данных сессии, маршруты трёх ролей, форматы уведомлений, конфликты времени и отправку форм. Go-тесты проверяют реальную регистрацию маршрутов и смену учётных данных с включённой и выключенной 2FA.

Если системный кэш Go недоступен, задайте `GOCACHE` в доступной папке, например в PowerShell:

```powershell
$env:GOCACHE = Join-Path (Get-Location) 'tmp/go-build'
go test ./...
```

## Сессия и уведомления

JWT хранится в `sessionStorage` и передаётся как Bearer. При восстановлении приложения загружается профиль. Ответ `401` очищает токен и кэш личных данных и открывает вход. Ответ `403` показывает отсутствие доступа и сохраняет сессию. После успешной смены почты или пароля нужно войти заново.

QR-код TOTP создаётся локально библиотекой `qrcode`; внешним сервисам секрет не передаётся. Двухфакторная проверка защищает смену учётных данных согласно действующей бизнес-логике API.

Уведомления загружаются только при открытии их раздела или нажатии «Обновить», поскольку GET-запрос помечает сообщения прочитанными. Поддерживаются массив и объект с `notifications`/`warning`, включая `null` вместо пустого массива Go. Настройки email и SMS отражают возможности сервиса; подключение реальной доставки не входит в проект интерфейса.

## Структура

```text
frontend/             React, TypeScript, Vite, React Router, TanStack Query
internal/controller/  HTTP-контроллеры Gin
internal/usecase/     Бизнес-логика и тесты
internal/adapter/     PostgreSQL и Redis
internal/auth/        JWT, blacklist, ограничения ролей
internal/worker/      Outbox и NATS JetStream
docs/                 Существующая Swagger-документация API
```

Работа и запуск по умолчанию локальные. Публикация приложения не требуется.
